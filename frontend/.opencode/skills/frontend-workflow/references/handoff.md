# Mainlevée / description de PR

Écrire pour un contributeur qui revient au projet après plusieurs jours d’absence.

```md
## Contexte

Pourquoi ce changement existe.

## Changements

Ce qui a changé, en quelques puces.

## Comment tester

Commandes et étapes concrètes. Ajouter des captures si l’UI change.

## Checks

- lint :
- format:check :
- build / typecheck :
- tests :

## Limites et suite à faire

Lacunes connues, non-objectifs assumés, prochaine étape.
```

Pour `format:check`, écrire le résultat réel si le script existe, sinon `N/A — script absent`.

Si le travail est inachevé, ouvrir une draft PR ou laisser un commentaire avec : état, bloquants, prochaine étape et fichiers déjà touchés.
